Can OpenCodex share an HTTPS API?

Short answer: yes — already supported, by putting a TLS tunnel (ngrok / Cloudflare Tunnel / Herd Expose) in front of local http://127.0.0.1:10100. Native TLS inside the Bun proxy is not the product path today. A new Laravel+Herd app is optional only if you want a PHP product layer — not required for HTTPS.

Like Warp share — but for an API

Warp shares a terminal session (human/agent UX). OpenCodex needs to share an OpenAI-compatible HTTPS endpoint. Same “give me a public URL” feeling; different wire.

Recommended

A · Tunnel in front of OpenCodex

  • Keep OCX as-is (Bun proxy)
  • ngrok http 10100 or cloudflared tunnel
  • Or Herd expose → localhost:10100
  • Set OPENCODEX_API_AUTH_TOKEN
  • Docs already cover this
Harder

B · Native HTTPS in OCX

  • Add cert/key config to Bun server
  • Cert lifecycle, renewals, SNI…
  • Duplicates what tunnels already do
  • Not needed for “share API”
Only if PHP product

C · New Laravel + Herd

  • Herd gives *.test HTTPS locally
  • Expose/Forge for public HTTPS
  • Laravel would be a gateway UI / SaaS shell
  • Still reverse-proxy to OCX or reimplement adapters
Wrong layer

D · Warp-style session share

  • Great for watching a terminal
  • Does not expose /v1/responses
  • Clients cannot point base URL there

Verdict

Do not rewrite OpenCodex in Laravel just for HTTPS. Use Approach A. Consider Laravel+Herd only if the goal is a separate product (team portal, keys, billing) that calls OpenCodex over HTTPS — not replaces it.
